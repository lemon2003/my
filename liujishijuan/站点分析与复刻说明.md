# pastpapers.cn/cet-6 站点分析与复刻说明

> 分析对象：https://pastpapers.cn/cet-6（大学英语六级真题分类页），辅以 `/contents`（目录页）与 `/paper/{slug}`（试卷阅读页）。
> 分析方式：抓取服务端渲染 HTML、静态资源（CSS/JS 分块）、页面暴露的分页接口，逐项核对 DOM 结构、样式令牌与交互参数。

## 一、【可验证事实部分】

### 2. 设计令牌（明/暗）

明色：`--background: 0 0% 100%`、`--foreground: 0 0% 3.9%`、`--muted: 0 0% 96.1%`、`--border: 0 0% 89.8%`、`--radius: .5rem`。

### 4. 交互与动效参数（读取自压缩后的组件代码）

- 卡片入场：`opacity 0→1`、`y 30→0`、`duration .5s`、`delay = 0.1 × 序号`，`viewport once, margin -50px`。
- 卡片悬停：`scale 1.05`，阴影 `0 2px 8px rgba(0,0,0,.05)` → `0 20px 40px rgba(0,0,0,.15)`，`duration .3s cubic-bezier(.4,0,.2,1)`。
- 顶部标题：`scrollTop < 48` 显示，否则 `-translate-y-3 opacity-0`，过渡 200ms。
- 返回顶部：`scrollTop > 480` 出现；点击 `scrollTo({top:0,behavior:'smooth'})`。
- 年份筛选：Popover 宽 192px、`p-3`、三列网格、首项「全部」；选中项 `bg-foreground text-primary-foreground`；选中后按钮右上出现 `h-2 w-2` 圆点；触发按钮 Tooltip 文案为「快速定位」。
- 无限滚动：哨兵元素 + `IntersectionObserver`（`rootMargin 0 0 500px 0`），每次加载 1 个月份分组，加载中显示 24px 旋转图标，无更多时显示「到底了」。
- 滚动位置记忆：进入试卷页前把 `scrollTop` 等写入会话快照，返回时恢复。

### 5. 数据与接口

- 分页接口：`GET https://pastpapers.cn/api/categories/{slug}/papers?page=N&limit=M`，返回 `{groupedPapers, hasMore, nextPage}`，`limit` 单位为「月份分组」。
- 分类页首屏由服务端渲染 2 个分组，其余按滚动追加。
- 分类元数据：`totalPapers: 76`，`availableYears: [2026 … 2015]`。
- 试卷详情数据（服务端注入）：`{title:'2026-06-CET6-1', year, month, pdfUrl, audioUrl, hasListening, answer, examFeatures}`；PDF 与 HLS 音频均为 `/uploads/*.pdf`、`/hls/*/playlist.m3u8`。
- 资源响应头 `Access-Control-Allow-Origin: *`，允许跨域读取 PDF。
- 单词翻译接口：`GET /api/translate?word=xxx`。未登录/非会员直接返回 **403** `{"error":"Forbidden","message":"仅限会员使用翻译功能"}`（实测 `abandon`、`knowledge`、`practice` 三个词均为 403）。更靠后的受保护接口还需先调 `solveHumanChallenge` 拿到 proof，放进请求头 `X-Content-Human-Proof` 才能访问。
- 生词本：`POST /api/vocabulary`，超限返回 `{"error":"Vocabulary limit reached"}`。
- 听力音频密钥：`GET /api/audio/key?paperId=…`，未登录返回 **401** `Unauthorized (Login Required)`。

### 6. 实测数据规模

共 26 个月份分组、76 套试卷，时间跨度 2015 年 6 月至 2026 年 6 月；每套含 1 张封面图（400×562）与 1 个 PDF。**76 份 PDF 合计 20.5 MB，最小/最大/平均为 0.09 / 0.34 / 0.27 MB**（全部实测 `Content-Length` 求和），体积很小，完全可整包本地化。49 套标注带听力音频。

> 听力音频实测：49 套全部为 `AES-128` 加密 HLS（`#EXT-X-KEY`），密钥接口 `GET /api/audio/key?paperId=…` 在未登录时返回 **401 Unauthorized (Login Required)**，带 `Referer` 与浏览器 UA 重试仍为 401。即在原站未登录状态下，听力音频本身也播不出来。

### 7. 目录页 `/contents`

5 个分类卡：考研英语（1998~2025，44 份）、四级（2015~2026，76 份）、六级（2015~2026，76 份）、专四（2009~2025，21 份）、专八（2009~2025，21 份）。卡片样式 `bg-card/45 + border + rounded-2xl`，左侧 4px 竖条在悬停时由上向下展开，右侧 `⟶` 从左侧滑入。

### 3. 与原站的已知差异（如实说明）

1. **背景底纹**：原站由 Web Worker 程序化生成 Canvas 底纹；复刻版保留同一套 `::after` 径向光晕与 18s 漂移动画，但未复现 Worker 绘制纹理（该纹理在明色主题下几乎不可见）。
2. **阅读器功能范围**：已实现 PDF 渲染、缩放、页码导航、页面目录、批注（画笔/荧光笔/橡皮/撤销/清空）、**点词查义**（含悬停词级高亮）、下载、全屏、主题切换；原站另外提供「整句翻译」「客观题作答」「答案解析」三类依赖其服务端（含加密下发的解析数据与鉴权）的功能，本地静态复刻无法等价实现，故未纳入工具栏。
3. **听力音频**：原站 49 套音频为 AES-128 加密 HLS，密钥接口要求登录（实测 401），无法解密。复刻版改从「午后书真题」（iget100.wuhoushu.com）取同套试卷的直链 MP3/M4A（`image.iget100.com/100/exams/{slug}/listening.*`，无鉴权）。现落地 **61 个文件 / 37 段录音**，覆盖 17 个考次，639 MB，单段 24.6–29.0 分钟。这不是缺口——六级每考次全国只考 2 套听力，第三套与第一套或第二套相同，真题 PDF 里明写「本套听力试题同第1套或第2套试题一致」。**已用语音转写逐段核对内容与试卷是否对应**：取每段开头 85–260 秒对话主题与真题听力第一题选项比对，发现 3 处错配并已处理——2017-06 实为 2017-12 录音（撤下）、2021-12 与 2023-12 的第 1/2 套音频互换（已对调）。2015–2016 年 12 套 + 2017-06 共 15 套暂缺，点击立即提示「该套听力音频暂缺」，不联网空等。清单见 `assets/js/audio-manifest.js`，明细与核验结论见 `assets/audio/放置说明.md`。
4. **账户体系**：原站为邮箱登录 + 服务端进度同步；复刻版为纯前端弹窗，仅做格式校验并把登录状态存到 `localStorage`，不上传任何数据。
5. **其他分类**：目录页中除六级外的 4 个分类为占位入口，点击给出提示。
6. **SEO 附属文件**：未生成 `manifest.json`、`sitemap.xml`、`robots.txt` 与站点图标集，仅内联了一个 SVG favicon。

### 4. 使用方式（本地离线，双击即用）

试卷 PDF 已全部下载到本地，站点不再依赖原站任何资源，**断网可用**。

- **浏览列表**：双击 `index.html`。
- **阅读试卷**：直接点卡片即可，PDF 会正常分页渲染、可批注。
- **听力**：61 套音频已随包放好，点「听力」直接播放（http 与双击两种方式都实测通过，点击到出声约 0.27 秒）；15 套（2015–2016 年 12 套 + 2017-06 3 套）暂无音源，点击立即提示。
- **可选加速**：双击 `启动预览.bat`（起本地 http 服务，PDF 走流式 + Range 分段，首屏略快）。

#### 为什么 `file://` 不能直接 fetch 本地 PDF

浏览器把 `file://` 的每个文件当作独立的 **opaque origin（`null`）**，而同源策略禁止跨源读文件——`fetch('assets/pdf/x.pdf')` 在 `file://` 下会直接抛 `URL scheme must be http or https`，`XMLHttpRequest` 同样被拦。这是防止恶意网页借本地 HTML 偷读整块磁盘，Chrome 从 2019 年起默认如此（`--allow-file-access-from-files` 已不推荐）。

**绕开办法：`<script>` 标签不受同源限制。** 于是把每份 PDF 转成 base64 存进 `assets/pdf-b64/{slug}.js`：

```js
window.CET6_PDFB64["2015-06-cet6-1"] = "JVBERi0xLjQK...";   // 仅示意，实际是一整行
```

阅读器检测到 `location.protocol === 'file:'` 时，动态插入该脚本 → `atob` 解码成 `Uint8Array` → 交给 `pdfjsLib.getDocument({data})`。全程零网络请求，所以双击就能读。代价是 base64 比原始 PDF 大约 33%（21 MB → 28 MB），且 `file://` 下 Worker 也被拦，PDF.js 会自动退回主线程渲染（实测 0.3 MB / 9 页的试卷渲染无感知延迟）。

其他可行但没采用的方案：① 让用户用 `<input type="file">` 手动选文件（每次都要选，体验差）；② Chrome 加 `--allow-file-access-from-files` 启动参数（要改快捷方式，且降低安全性）；③ 把 PDF 直接塞进 `data:` URL（与 base64 等价但无法按需加载）；④ 打包成 Electron/Tauri 桌面应用（体积和复杂度都远超需求）。

> 说明：`assets/pdf/` 与 `assets/pdf-b64/` 内容重复，共约 49 MB。若只在 `启动预览.bat` 下使用，删掉 `assets/pdf-b64/` 可省 28 MB；若只双击使用，删掉 `assets/pdf/` 会让「下载试卷」按钮失效。两者都保留是为了兼顾。

## 三、点词查义：原站怎么做，我们怎么做

### 原站（读自 `5009a5e0c0d494e0.js`）

1. **取词**：PDF 只是图形，没有字符信息，所以它在每页画布上叠一层 `.text-layer`——PDF.js `renderTextLayer` 生成的透明文字层。点下去时用 `document.caretRangeFromPoint / caretPositionFromPoint` 拿到光标所在的文本节点和字符偏移，再向两侧扩到字母边界，得到一个完整单词。
2. **查词**：`fetch('/api/translate?word=…')`，200ms debounce，带 `AbortController` 取消上一次请求；429 时提示「单词翻译过于频繁，请稍后重试」。
3. **权限**：`/api/translate` 对未登录访客直接返回 `403 {"error":"Forbidden","message":"仅限会员使用翻译功能"}`；其后的受保护接口还要先过 `solveHumanChallenge` 人机验证，把结果放进 `X-Content-Human-Proof` 请求头。也就是说这是个**会员功能**，不是普通访客点一下就有。
4. **附带**：单词可存进生词本（`POST /api/vocabulary`，超限返回 `Vocabulary limit reached`），还有整句翻译卡片（`SentenceTranslationCard`）。

### 复刻版（离线，无任何接口）

取词方式与原站**完全一致**（透明文本层 + `caretRangeFromPoint` + 字母边界扩展），差别只在查词这一步换成**本地词库**：

| 环节 | 原站 | 复刻版 |
|---|---|---|
| 文字层 | PDF.js textLayer | 同（`pdfjsLib.renderTextLayer`） |
| 取词 | caretRange + 字母边界 | 同 |
| 查词 | `/api/translate`（会员） | `assets/dict/cet6.js` 本地查表 |
| 变形还原 | 服务端 | 词表内置 7138 条变形 + 规则还原（-s/-es/-ies/-ed/-ied/-ing/-ly） |
| 发音 | 服务端音频 | 浏览器 `speechSynthesis`（系统英文语音） |
| 副产物 | 生词本 | 无（写本地生词本意义不大） |

**词库怎么来的**：用 `pypdf` 提取 76 套试卷全文（180.7 万字符）→ 正则分词得 **16600 个唯一词** → 与开源词库 ECDICT（MIT 协议，`skywind3000/ECDICT`）比对，命中 **14874 个（89.6%）** → 每词只留音标 + 最多 3 条释义、单条截断 120 字，连同 7138 条变形索引一起压成 1.28 MB 的 JS。未命中的 1726 个多是 PDF 提取出的粘连词（如 `actuallybenefit`、`accessto`）与专有名词，点到时提示「本地词典未收录该词」。

**悬停高亮**（复刻版新增，原站没有）：文字层是透明的，鼠标划过时看不出会点到哪个词。指针模式下加了词级高亮——`caretRangeFromPoint` 取到词后，用 `Range.getClientRects()` 的矩形直接套在这个词上（不是整行、也不是整个 span），2px 外扩 + 黄色描边，与选区同色系。为避免「页边空白处凭空标出一个远处的词」，先用 `elementFromPoint` 确认命中的是 `.text-layer`，再校验鼠标点与词矩形的距离。`requestAnimationFrame` 节流，词和位置没变就不碰 DOM；滚动/缩放时按最后鼠标位置重算；切到画笔、划选文字、鼠标移出页面区时自动隐藏。

卡片定位规则：**优先放在词的上方**（压住的是刚读完的行，不挡接下来要读的正文），只有上方剩余空间小于 108px 才翻到下方；两侧都紧张时压缩卡片高度并在卡片内滚动，而不是越界或盖住正文。点词的 click 处理里加了 `stopPropagation()`——否则同一个事件会继续冒泡到 `document` 的「点外部关闭」监听，卡片刚 `show` 出来就被关掉，表现就是「只有第一次点得动」。

**限制**（如实说明）：① 一个单词被 PDF 拆到两个 span 时不做跨节点合并，可能只取到片段；② 只收试卷里出现过的词，点在词汇表外的词查不到；③ 没有例句、词形变化表和生词本。

## 四、【个人推测部分】

1. 原站把月份分组作为分页单位（`limit=1` 表示一屏一组），推测是为了让首屏 HTML 体积可控，同时让滚动加载的节奏与内容密度匹配；分组数量固定为 26 组，因此总请求数很少。
2. 阅读器的「翻译」「解析」在请求中携带加密数据字段（`encryptedData`）并经过解密后渲染，推测是付费或登录权益的内容保护手段；其 429 提示（「访问过于频繁」）说明后端对这些接口做了频率限制。
3. 单词翻译加了 `X-Content-Human-Proof` 人机校验与 200ms debounce，推测主要不是为了防刷会员额度，而是防止有人拿它的接口批量导出整本词汇对照表——这类站点最容易被扒的就是「原文 + 译文」的平行语料。
4. 底纹 Canvas 采用 Worker 生成并按明暗主题各缓存一张，推测是为了避免主线程在低端设备上卡顿，同时靠透明度极低（约 3.5%）的叠加制造纸张质感。
5. 站点以 SEO 为导向（每篇试卷页有独立的 title/description/OG 标签与 canonical），推测分类页的分页设计也在服务于「收录更多内页」的索引策略。
